# Architectural Decision Records (ADR)

This document records the foundational architectural decisions and the technical opinions defended in the Team of Six (TOS) project. 

| title | context | decision | consequence |
| :--- | :--- | :--- | :--- |
| **Trimodal Team Architecture** | Standard AI coding tools grant LLMs direct file access, leading to cognitive collapse and security risks. | Split the development cycle into three functional personas: **Architect** (Wisdom/Review), **Agent** (Reasoning), and **Ghost** (Execution). | High-integrity development; the Architect performs PR-style reviews and test execution in a local environment before merging Ghost mutations. |
| **The Contextual Trinity** | LLMs lose reasoning accuracy when the task surface is too broad or the context window is cluttered with irrelevant history. | Structurally enforce a **1:1:1 mandate**: exactly one Issue, one Branch, and one Feature per workspace. | Physical isolation of work that eliminates scope drift and ensures the Agent is grounded in a specific, narrow logic. |
| **Ephemeral Outbox Grounding** | LLMs suffer from "prompt drift" when relying on chat memory and lose track of the actual repository state. | Reject long-term chat history; regenerate a verified context document (the Outbox) directly from Git on every workspace transition. | Every turn starts in a "Clean Room" snapshot, forcing the Agent to derive logic from the current "Remote Truth" of the repo. |
| **Plaintext IPC Protocol** | Structured formats like JSON or YAML frequently cause parser failures due to LLM syntax errors (nested brackets, escaping). | Use a flat, plaintext protocol utilizing uppercase markers (e.g., `===TOS_CODE_START===`) for Inter-Process Communication. | Dramatic increase in generation reliability; the Ghost parses blocks via simple regex, and the Agent saves tokens for reasoning. |
| **Isolated Ghost Sandbox** | Executing AI-generated commands in a human's local environment risks data loss, credential theft, or environment pollution. | All file mutations occur in a restricted Unix user sandbox (`/mnt/team_of_six/sandbox/`) isolated from the Architect's home directory. | The Architect's local environment remains the "clean" space for verification; AI work is treated as an external contribution. |
| **HITL Micro-Protocol** | LLMs often "rush to code," skipping critical reasoning steps and resulting in syntax-heavy hallucinations. | Enforce a 4-step cognitive cadence in the system prompt: **Mirror**, **Challenge**, **Plan**, then **Execute**. | The Architect validates the Work Breakdown Structure (WBS) before code is written, ensuring lead-level oversight of junior-level labor. |
| **Shell-Centric Engine** | Compiled languages or heavy frameworks add overhead and opacity, making it difficult to audit AI-triggered actions. | Implement the gateway and core logic modules using **Zsh** scripts and standard Unix tools. | The framework is lightweight, audit-friendly, and natively composes with standard Git and GitHub CLI tools. |
| **Lock Hierarchy** | Writing to the filesystem during brainstorming or planning phases causes state corruption and unnecessary I/O. | Segregate work phases via atomic locks: **Soft Lock** (Trinity 0) for planning and **Hard Lock** (Trinity N) for code mutation. | Mechanically prevents the Agent from hallucinating syntax changes during ideation until the Architect explicitly grants write access. |
